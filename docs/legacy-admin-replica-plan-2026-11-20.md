# 旧后台高保真复刻：源码复核与实施方案

日期：2026-11-20。当前实现基线：`40af6b0`。对照对象：`/www/wwwroot/zjmf-manger-decoded/public/admin` 当前磁盘版本（项目标识为 3.7.7 自维护分支，来源于 3.5.8 解密工程）。

状态：**本轮完成分析与实施清单，应用页面尚未替换**。用户要求“直接复刻旧的后台，能还原的尽量还原”，并已明确确认：**恢复旧版顶部业务域＋左侧当前域菜单，整体尽量还原**。这项新决定取代此前“全局菜单全部左置”的界面约束。U2 已交付的权限、查询、来源恢复与业务 Action 继续复用；本方案重新确定展示结构。

## 1. 结论：按旧页逐一还原结构

前几轮采用的是“统一新外壳＋通用工作台”的设计目标，结果形成了新的使用方式。U2 虽解决了瀑布流和操作靠后，仍与旧版存在这些实质差异：

| 对象 | 旧版真实结构 | 当前 U2 | 复刻目标 |
| --- | --- | --- | --- |
| 全局导航 | 顶部业务域，左侧当前域菜单 | 六组全局左侧树 | 恢复旧业务域切换与上下文侧栏 |
| 客户摘要 | 身份与操作窄列＋工单／财务／产品业务宽列 | 账户资料／资金服务两张近等宽卡 | 恢复旧摘要分区、统计直达和客户身份条 |
| 实例详情 | 客户工作区内；主机切换；产品、财务、配置、自定义字段四组 | 独立五页签＋右操作栏 | 恢复客户上下文、旧四组布局与就近操作 |
| 账单详情 | 账单信息→交易明细→账单项目→操作日志 | 历史页签＋左右栏 | 恢复旧紧凑单页及动作弹窗 |
| 商品管理 | 售卖商品列表／商品编辑，与上游资源目录分开 | 连接、经典商品列表、导入与只读详情混合 | 恢复独立的售卖商品工作区与供应商工作区 |
| 列表／设置 | 紧凑表格、展开高级筛选、表单及按钮固定位置 | 大标题、独立卡片与较松控件 | 对照旧页恢复密度、行距、筛选和动作位置 |

这轮以**原页面的布局和操作顺序**为验收依据；不再把所有详情统一成同一种“双栏＋页签”模板，也不预填还原百分比。

## 2. 能还原到什么程度

### 2.1 外观、层级与已有操作可直接重建

- 顶栏、侧栏、主区尺寸、颜色、字体、表格、按钮、表单、分页、页内菜单、弹窗的外观与排列。
- 客户→产品服务→实例→账单／交易记录／工单的连续动线；现有全局搜索的分域结果可放回旧顶部位置。
- 已有资料编辑、账户停用恢复、标准密码重置、钱包加扣款、线下收款、全额退款、实例同步／生命周期／机器命令等，保留同一 Action，按旧操作位置呈现。
- 详情中原有记录、金额、只读配置和服务事实，采用旧标签与分组，但继续准确表达现有业务含义。

### 2.2 只影响局部还原的实际能力差异

| 旧界面内容 | 现状与复刻处理 |
| --- | --- |
| 客户公司／销售／分组折扣／跟进／附件／信用额 | 当前缺完整数据或操作；相应入口暂不展示。常用姓名、邮箱、手机、实名、账户状态及钱包继续完整呈现 |
| 一键代客登录 | 当前没有独立身份与会话协议；不把重置链接冒充代客登录 |
| 实例改到期日／续费价／过户／直接应用配置 | 现有事实可按旧位置展示，编辑按钮随实际能力提供；本次 UI 复刻不引入这些新商业规则 |
| 商品十页签内的全部保存能力 | 已有展示编辑／目录同步／降价边界可接通；当前其他字段分别属于只读上游事实、有消费者但无受控编辑、或尚无消费者，按原字段清单分项处理 |
| 手工建单／任意标记已付／部分退款／合并账单 | 当前没有等价完整协议；使用已交付的普通线下收款与全额退款，不用旧按钮文案冒充其他行为 |
| 多商品订单、信用额、发票和合同 | 与现有账单／任务数据模型不同；不能仅换菜单名称就宣称已交付 |

原三列钱包继续保持可用、账单冻结、结清冻结各自含义；原支付计划与实际收款仍需分清。页面可以高保真，不能把含义不同的数字填进同一个旧字段。

商品详细证据与字段生效关系见 [已有字段清单](admin-product-workspace-u2-boundaries-2026-11-20.md)。该清单中的历史导航建议由本方案替代，字段事实仍适用。

## 4. 菜单恢复为旧业务域，现有入口完整安放

沿用旧域顺序，服务端按各叶子权限生成当前域菜单，空域不展示。总览仍可从 Logo 进入。分类位置不扩大 Gate；例如上游运维仍能访问其原绑定异常案件。

| 旧业务域 | 当前能力的安放方式 |
| --- | --- |
| 客户 | 客户列表与客户工作区；已有推广返佣放运营管理分类 |
| 业务 | 服务实例、已付待交付与相关履约入口；旧多商品订单审核不伪装成现有账单列表 |
| 财务 | 账单、交易流水与回调、应收、钱包结清、佣金转钱包、外部提现、资金异常 |
| 工单 | 工单列表、当前会话及独立工单处理页 |
| 功能 | 当前可用的卡密库存、库存概览、任务／通知事件等扩展与运行入口 |

## 5. 各核心页面的具体还原

### 客户列表与客户工作区

客户列表恢复旧工具栏、高级筛选展开、紧凑表格及底部分页位置。旧版“新增客户”等操作只有在后端实现后显示；当前已有搜索项完整保留，不能只做装饰性排序或搜索按钮。

详情恢复持续的客户身份 Flag 和旧式水平对象菜单。按可用能力恢复“摘要、个人资料、产品服务、账单、交易记录、工单、日志、通知日志”等名称与顺序；实名记录保留明确入口。旧开发者、信用额、附件、跟进等缺失项不展示。

摘要左列放身份、联系方式、状态和已有操作；右列恢复工单、财务、产品服务摘要。旧 CSS 在 992–1500px 覆盖列宽为约 3:7，不能只按 render 中的 5:19 推断 1440px 下的布局。摘要需要新增的工单状态／服务类型计数，采用受原模块权限控制的本地有界聚合；收支指标先明确流水口径，不能把钱包余额当营收。

个人资料采用旧式独立表单，复用原资料 Action 与安全回填。各记录仍按当前对象、当前内容查询，不恢复先查询所有数据再前端隐藏的方式。

恢复两类独立工作区：

## 6. 技术路线

推荐：**自定义旧版后台布局＋按旧页还原 Blade 内容，继续使用现有 Laravel 查询、Gate、session 和业务 Action。**

Filament 可以保留页面注册、登录和原权限；页面外壳通过其现成布局扩展点替换，而不是继续叠加颜色覆盖。当前版本 [Page::getLayout()](/www/wwwroot/Laravel13idc/vendor/filament/filament/src/Pages/Page.php:88) 和 [BasePage::render()](/www/wwwroot/Laravel13idc/vendor/filament/filament/src/Pages/BasePage.php:70) 已提供页面布局选择。自定义布局仍需保留原基础资产、CSRF、Livewire、消息及退出流程，机器菜单 POST 的专用壳也要一起适配。

本次复核旧 SPA 有 275 个 JS 文件，未找到 `.vue` 源组件或 SPA source map；42 个 `.map` 均在插件模板的第三方库目录。旧应用还依赖 localStorage 的 token／menuList／userInfo、旧 `rule` 树、Vuex 状态和旧接口返回协议。直接把 index.html／js 放进新项目，需要大范围请求层重写或旧 API 兼容层，成本和耦合都超过页面复刻。

因此以编译 render 和 CSS 为还原依据，抽取必要样式及素材，建立隔离的旧版样式命名空间；不全量导入带 `data-v-*` 选择器的旧样式。现有 SSR 和少量交互脚本足以承载本批结构，不必为外观引入 Vue 构建工程，也不需要卸载 Filament。

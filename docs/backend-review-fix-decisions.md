# 本次复审修复的设计决定

日期：2026-11-18。范围为本轮复审的十项缺陷，不包含原已延期的六项能力。

以下三项涉及现有冻结规则或数据库结构。用户已在本次会话明确选择“采用三项定向方案”，批准以下限定设计。批准不包括部署迁移、真实供应商写入或历史数据修复。
依据 `docs/agent-guardrails.md` §1.3："Changing them requires a human decision"，以及 §4 的不变量/schema 停止条件，已完成所需定向决定。

## A. 自动续费账单的付款选择

现有 INV-I1 要求总额与钱包/网关分配在创建时一次确定；定时器提前建单时不知道客户选择。

提案：只有新建且明确标记为自动生成的 Unpaid 续费单，才允许账单所有人在首次付款前确认一次钱包/网关分配。总价、报价、优惠券和续费边界保持原快照，不重新计价或重新消耗优惠券。要求未到期、没有任何付款 attempt、冻结/结算/解冻流水或未决履约。按 users→invoices→payment_attempts→instances→tasks 锁序提交；一次冻结、纯钱包 Paid+履约原子提交。保存确认请求及选择，同请求重放无副作用，变更意图拒绝。确认后恢复不可改分配规则。历史未标记账单不推断为自动单。

需要对 INV-I1 和章程的分配部分作上述定向例外；不允许通用修改未付账单、不重开终态、不改历史流水。终止服务时取消未付续费并按原账本解冻，是现有写入者/状态范围内的独立兼容修复。

验收：定时建单→客户选钱包/支付宝→金额与实际一致；部分钱包、全钱包、重复确认、并发付款、已有 attempt、到期/终态、优惠券变化均验证；旧回调仍依原单决策表处理。

## B. 终止旧资源后的显式换绑

现有 INV-S1 禁止 Deleted 回到 Active/Suspended；正常终止会写 Deleted，而 terminate 换绑要求旧上游已经 Deleted。

提案：仅授权管理员通过现有显式换绑 Action、选择 terminate、填写原因并确认时，允许将 Deleted 的逻辑服务绑定到已认证的新 Active/Suspended 主机。旧上游须再次认证为 Deleted，目标产品/周期/币种需验证；存在退款或未决财务/任务即拒绝。保留旧绑定历史，旧任务失效，轮换回调 token，审计记录终止状态和新绑定。普通同步、续费、自动任务均不得复活终态。

需要 INV-S1 的严格定向例外，不增加状态或 schema；已退款实例继续终态。

验收：正常终止→Deleted→管理员换绑闭环；无权限、未确认、keep_orphan+Deleted、已退款、未决资金、目标不符、认证配置/绑定并发变化均拒绝，旧请求不能覆盖新绑定。

## C. CMS 历史地址

保留现有按 ID 修改 slug 的行为，新增两张有唯一索引的历史 slug 表：栏目别名按(type, slug)唯一指向栏目；文章别名按(category_id, slug)唯一指向文章。栏目改名不复制其全部文章路径，解析先定位栏目（当前名或历史名），再定位文章（当前名或历史名），一次 301 到最终规范 URL，避免跳转链。

别名永久保留且不能被另一对象复用；重用本对象别名可直接切换规范名。只有当前公开可见目标才能重定向；下架/隐藏/未来发布仍 404。HTML 和 .md 保留原格式；sitemap 仅当前地址。改名和保留旧名在同一事务内，唯一索引处理并发冲突。

需要新增迁移和索引，但只在隔离数据库验证；现有业务/预览库迁移仍是独立部署动作。此实现不能自动找回本轮修复前已丢失且无可靠历史记录的地址。

验收：栏目/文章连续改名、二者同时变化、不同栏目同文章 slug、冲突复用、隐藏/下架、.md、并发改名、当前地址 canonical/sitemap。

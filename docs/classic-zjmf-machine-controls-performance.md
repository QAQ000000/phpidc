# 机器管理入口读取性能

## 原因与改动

客户反馈的按钮是“机器管理：电源、重装系统、救援、VNC”。原 ReadInstanceControlsAction 复用全量 panel widgets：一次 header 后，再读取 STATUS、四张监控图表，以及可能存在的面板登录 HTML。控制按钮、系统分类和版本其实全部来自 header，这些额外网络请求使机器管理沿用约 26 秒的监控延迟。

现在由 Action 固定选择 cloud_controls，经 DriverManager 构造本次读取所用的驱动；ZjmfPanelProtocol 在执行 I/O 前选择模块，只请求一次 `/host/header`，本地解析当前能力和 OS 配置。没有从客户输入接收 widget 选择。未指定选择的其他调用继续保留全量行为。

入口提交后立即显示加载提示、aria-busy 并禁用重复点击；浏览器返回该页时恢复按钮。不改变普通 POST 和无 JS 时的页面流程。

## 规则和边界

- 不修改冻结的 HasCustomPanelWidgets、PowerControllable、DTO、枚举、表结构或业务不变量（agent-guardrails §1.3）。仅对具体服务、驱动构造及内部协议增加可选读取选择。
- Action 通过能力接口和 DriverManager 调用，不按供应商名称分支（§1.5）。驱动选择模块后再调用网络，不以“先读全部、再过滤输出”冒充优化。
- 仍验证本人、Active、有效上游账户及已绑定服务，header 必须返回上游 Active；HTTP 返回后复验归属、状态和绑定，不缓存旧管理配置。不跨 HTTP 持有数据库事务（INV-L3），日志仍经 CallUpstreamAction（INV-U1）。
- 真实电源/重装/救援/VNC 提交仍执行原有实时 header 复验、参数校验、确认、原因审计、请求去重及未决结果保护。本次没有用页面加载时的能力取代执行前复验。
- 不更改上游超时策略；只移除管理页不需要的请求。此处读取不改变资金、账单或履约任务。

## 验证与剩余限制

ClassicMachineControlTest 增加四个实例：管理页即使同时广告电源、全部图表和登录入口，也只能读取 header；读取期间分别改变归属、状态、host 绑定时必须丢弃结果。原有断言不变，完整监控、面板登录和真实命令的既有测试继续通过。

Pest **547 passed / 4321 assertions**，PHPStan **0 errors**，Pint **clean**；Specs 剩余 **0**。

完整监控仍聚合读取多个远端接口，PHP 内置预览仍单进程；同时发起慢监控时，管理入口依然可能排队。3.9 秒是此次无其他长请求时的样本，不是响应 SLA。本轮按用户要求保留现有运行服务，未重启、更换监听端口或停止浏览器。真实电源/重装/救援变更仍未执行，本次性能验收不替代这些破坏性功能的真实联调。

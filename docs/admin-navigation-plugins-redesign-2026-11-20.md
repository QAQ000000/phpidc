# 后台统一导航与插件管理实施记录（2026-11-20）

用户要求所有后台菜单集中在左侧、分类可展开收起，移除内容区的第二套侧栏及分类菜单；易支付作为支付插件，邮件和短信各自最多启用一个实现。本批复用现有表、角色和配置 Action，无新增迁移。

## 页面与菜单

全局导航由 `AdminNavigation` 统一构建，采用 Filament 原生可折叠分组和移动抽屉。一级分类下直接展示叶子菜单，无嵌套侧栏：

| 分类 | 入口 |
| --- | --- |
| 商品与服务 | 库存概览、卡密库存、已付待交付、上游商品与连接、上游服务 |
| 财务与结算 | 财务账单、流水与支付回调、退款佣金应收、钱包结清、外部佣金提现、佣金转钱包审核、支付方式、计费策略 |
| 运营与内容 | 优惠券、推广规则与佣金、工单处理、商城与内容、下载资源 |
| 消息与通知 | 通知模板与日志、通知事件与投递、邮件插件、短信插件 |
| 系统设置 | 站点信息、实名认证、第三方登录、自动化策略 |
| 系统运维 | 任务监控与恢复、业务异常核对、账户角色管理、操作审计 |

导航沿用原 Page 的可见权限，空分类隐藏；当前分类初始展开，其余可收起。同一路径不同配置 tab 独立高亮，旧配置地址仍有效。账单、机器核对、配置映射核准等依赖记录的详情页隐藏导航项，归属原业务菜单。配置映射核准操作页也接入全局后台壳，原 URL、检查/提交和权限保持。

系统配置页只显示当前列表或表单，彻底移除内层导航及小屏分组下拉。表单内部的字段标题、筛选和记录操作保留。文章内部预览仍使用无脚本的前台预览窗口，以核对发布效果；它不是后台分类入口。

## 插件列表与启停

`InstalledPlugins` 只列出已实现的内置适配器，元信息如实标记“项目内置适配器 / 随系统发布”。列表包含 ID、名称、标识、描述、作者、版本、状态和操作；没有虚构的可启用驱动或安装/卸载能力。

| 分类 | 当前实现 | 启用关系 |
| --- | --- | --- |
| 支付方式 | 易支付 | 支付宝、微信是该插件的内部渠道，配置页保留独立开关 |
| 邮件 | SMTP、日志模拟 | 同时一个，复用 `mail.transport` |
| 短信 | 智简魔方、日志模拟 | 同时一个，复用 `sms.driver` |
| 实名 | 智简阿里认证 | 沿用已有 `kyc.enabled/driver` |
| 第三方登录 | GitHub、Google、QQ、微信、Telegram | 可并存，逐个启停 |

启用前验证已保存配置；未配置时界面提示先配置，直接 POST 仍由业务 Action 拒绝。停止 SMTP/真实短信会回退为日志模拟，并不停止通知事件产生；日志模拟不能被单独关停。手机绑定开启时，必须先在短信配置关闭绑定，才能切回日志。Telegram 登录停用仅控制登录，机器人通知和已保存 token 保留。

易支付整体启停只更新已有两个渠道标志，在原配置元数据锁下授权、验证和审计；不生成或改写商户快照、支付尝试。历史回调仍按原快照核验。原有渠道缺省启用语义保持，未配置商户会显示“待配置”，不代表已通过连通测试。

## 配置、安全与兼容

新配置表单携带固定白名单 `plugin_context`，回到对应插件配置；旧 POST 未携带该字段时继续原跳转。保存接口参数不会隐式启用邮件、短信、实名或登录插件，相关启停字段只在插件列表操作。易支付子渠道必须成对提交，均未提交则保留现状。

密钥只向页面投影是否已配置，输入始终为空；空白保留已存密文，失败不回闪明文，审计仅记录键名。启停和保存均要求原分域权限、锁内有效管理员重查，表单保留 CSRF。显式测试仍使用当前已启用通道与本人已验证目标，原独立限流、未知结果不自动重发保持；日志通道在界面明确标记为模拟。

本批不修改生产支付/通知凭据，不执行真实付款、供应商动作或邮件短信发送。当前插件为内置驱动管理，动态安装第三方包与扩展打包协议不在本次实现范围。

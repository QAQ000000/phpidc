# 客户账户与本人订单/服务交付契约

日期：2026-11-17。本轮继续既有 C15，不新增表字段、枚举或冻结契约，不修改原测试与 Specs。

后续真实服务适配实现与最新 Gate 见 `identity-provider-integration.md`；已新增国内短信、个人实名轮询及 Telegram 绑定/通知实现，真实 SMS/KYC 服务按用户要求跳过并保持关闭。下文305用例及未接适配器是本次门户交付时的记录。

## 页面和访问边界

- `/register` 独立注册页；`/login` 登录页，含找回密码、注册和已配置第三方登录入口。注册只接受姓名、邮箱、密码，邮箱统一小写，不能注入余额、角色、认证状态或手机号。大小写重复邮箱及已软删除账户邮箱不重新注册。
- 登录支持记住登录。客户入口要求认证；未登录打开本人页面或邮箱验证链接，登录后回到原站内地址。只接受 `/console` 范围及 `/email/verify/` 的返回路径，外站和后台目标不作为客户登录跳转目标。
- `/console` 总览：本人账单/服务数量、最近记录及账户验证提示，保留购买入口。
- `/console/invoices` 本人账单：每页 20 条，按账单状态和账单号/商品名搜索；`/console/instances` 本人服务：每页 20 条，按状态和名称/IP/商品名搜索。分页不再截断到 50 条；搜索的 OR 条件始终位于本人范围内。
- 账单详情只展示已存客户金额、明细白名单、创建/付款/到期时间及本人关联服务；不重新计算金额，不输出上游成本、购买私密快照或回调原文。
- 服务详情展示本人服务状态、到期/续费信息、关联本人账单和既有控制入口。卡密/密码仅沿用已交付 Active 服务的所有者详情展示，不放在列表、搜索或总览，不在 GET 时调用上游。
- 其他人的详情和写操作继续 403；游客 HTML 请求跳转登录、JSON 请求 401。客户端提交 user_id 不影响任何列表范围。客户页面 private/no-store/no-referrer。

## 沿用与待配置流程

找回密码、邮箱签名验证、四平台登录绑定、手机号验证码、C15 实名状态事务沿用 `cms-identity-decisions.md`。本轮补齐登录后继续原邮箱验证链接的行为，保留绑定前本地已验证邮箱/密码要求，不按第三方邮箱合并。

真实短信与实名供应商仍未选定；不猜端点、不伪造验证、不收明文证件、不将 LogSmsDriver 返回 true 当作投递。用户已被询问服务名称、文档与专用测试配置位置；这些信息未到位前不实施真实适配。Telegram Widget 同样保持待核实。

# 后台账单与实例页面合同

日期：2026-11-20。基线：商品列表样板提交 `f8614f0`。本批承接 `admin-ui-page-contract-2026-11-20.md`，只推广已有公共组件与页面组织，不修改金融、供应商或生命周期规则；验收结果另写实施记录。

## 1. 页面范围与导航

| 页面 | 主要任务 | 内容顺序 |
| --- | --- | --- |
| `/admin/finance` | 查找账单、比较存储金额、进入核查 | 页头操作、真实筛选、账单表格、分页 |
| `/admin/finance/invoice?invoice_id=ID` | 核查单张账单、支付记录与既有退款入口 | 返回入口、金额与业务事实、退款操作、支付尝试、回调记录、续费恢复信息 |
| `/admin/upstream-instances` | 查找经典魔方服务、识别状态与到期情况 | 页头说明、真实筛选、服务表格、分页、明确范围的最近任务 |
| `/admin/upstream-instances?instance=ID` | 查看一件服务并操作原有生命周期与换绑 | 返回入口、当前绑定与计费事实、关联任务、原有操作与核对链接 |

继续使用 Filament 面板和唯一的全局左侧导航：6 个可折叠分类、30 个入口，实际可见项仍按现有权限过滤。账单详情高亮“财务账单”，实例详情高亮“上游服务”；不新增入口、内层侧栏、分类 Tab 或手机菜单下拉。`invoice_id`、`instance` 只选择记录，不能充当分类菜单。

实例页只管理 `DriverType::ZJMF_API`；不能因为换了表格就称作全部驱动的机器管理。客户控制台、商城选购和其他财务页面不属本批，不套用选配页的悬浮报价汇总。

## 2. 复用与请求合同

复用现有 `x-admin.card`、`filters`、`table`、`badge`、`pagination` 和需要时的 `dialog`，沿用 `filament.admin-ui-styles`。金额与操作右对齐，次要 ID/原始状态作辅助文字；表格使用语义表头、独立滚动容器及固定表头。只补当前页面所需结构，不引入通用表格引擎、任意字段编辑器或新的 UI 框架。

列表、筛选、分页和记录详情 GET 只读本地事实，不自动读取上游、同步资源、核价、重试任务或提交操作。只有用户显式提交原有 POST 才进入现有业务 Action。列表选取显示必需字段；详情才查询当前记录的关联事实，不为整页每条记录加载支付历史、任务载荷、完整配置或凭据。

筛选使用有标签的 GET 表单；查询和重置都回到第一页，服务器分页稳定排序并保留已验证的有效筛选。输入校验类型、长度、ID 正整数与枚举范围；非法数组或未知状态不得被强制转换为其他条件或触发 500。不存在、驱动不符或非法详情 ID 明确返回错误，不能默认选中第一条记录。

## 3. 财务账单

### 3.1 列表

支持完整账单号 `invoice_no` 精确匹配、客户 ID `user_id`、真实 `InvoiceStatus` 与 `InvoiceType` 筛选；未实现的日期、金额、渠道筛选不画到界面上。结果按账单 ID 倒序、每页 20 条，空结果区别于尚无账单。

行内展示账单号/本地 ID/客户、业务类型与状态、总额及币种、钱包/网关分配和“核查”入口。业务类型覆盖新购、续费、升级、降级、钱包充值；保留原枚举语义，使用中文标签时必须准确对应原值。

金额直接展示已保存的定点字符串，不通过浮点或前端重新计算。`total_amount = credit_applied + gateway_amount` 是原账单事实；优惠已经计入总额，不能再次扣除。不同币种不合并求和，也不新增无依据的统计总额。

`Paid` 表示支付已入账，不等于服务已开通；钱包充值 `Paid` 可以标“已到账”，不生成服务/交付语义。支付尝试状态、回调处理结果、账单状态分别展示，回调被收到不等于该笔钱已成功结算。

钱包充值设置若收进页头对话框，仍仅向 `finance.wallet.configure` 显示；保留原 URL、启停值、真实原因、确认、固定 CNY 1.00–10000.00 和“旧有效单继续支付、充值不支持退款”的说明，不在本批变更该设置边界。

### 3.2 单据核查与退款

详情保留客户/商品/服务关联、账单类型、币种、总额、优惠、钱包/网关分配、预计上游成本及支付/到期时间。无关联服务、成本或时间显示“—”或明确缺失，不用零替代未知值。

支付尝试和回调各自分页，保留 `attempts_page`、`callbacks_page` 与 `invoice_id`，不能翻一页就丢失当前账单或重置另一表的条件。字段限于原有订单号/交易号、网关、金额、状态/结果、时间等核查事实；不展示回调原文、签名、历史商户密钥、支付 URL、加密订单或完整请求快照，也不把它们带入 Livewire 公共状态。

退款入口继续受 `finance.view`、`finance.refund` 与记录级 `refund-invoice` Gate 保护，后端继续独立授权。仅对当前允许的 Paid 非充值账单显示可提交操作；充值单仍不支持退款，终态只给核对说明。

原 POST `/admin/finance/invoices/{invoice}/refund`、CSRF 与字段 `mode`、`reason`、`keep_service`、`external_confirm`、`confirm` 不变。全额退款、外部退款已完成登记、保留服务的损失豁免必须说明清楚：外部登记不实际打款，豁免仍需真实原因和单独勾选，不能用普通可选备注替代。普通已终止服务退款沿用可选备注，不额外增加确认层或强制原因。

保留流水/回调链接、按 `tasks.view` 显示的关联任务入口及只读续费恢复链；运营不能通过 UI 代客户核价、扣钱包或重开旧单。保存失败时在用户实际操作区域展示校验与业务错误，保留允许回填的非秘密字段。

## 4. 经典魔方实例

### 4.1 列表与任务

本地支持名称/明确 ID、所属连接、`InstanceStatus` 等实际实现的筛选；搜索框说明可匹配范围，不能暗示查询尚未实现的 IP、客户邮箱或远端实时资源。列表展示实例名/ID、连接/上游主机 ID、真实状态、到期时间、续费金额与币种、详情入口。续费金额是当前本地约定，不误称上游实时成本或下一张账单最终价格。

`Active`、`Suspended`、`Pending`、`ProvisionFailed`、`Cancelled`、`Deleted`、`Fraud` 分别使用准确文字。`Deleted` 不表示本地数据被物理删除，`Suspended` 不等于已终止；`last_synced_at` 只表示最后记录的同步时间，不表示当前远端可达。

最近任务必须说明“经典任务”或“当前服务任务”及实际截取范围。列表避免给每行同时铺开完整操作表单；详情只展示当前服务的相关任务。任务 `pending/running/success/failed/stale` 与实例状态分别标记，`stale` 不写成仍待执行；错误仅按既有可公开诊断展示，不复制任务 `payload`、远端请求/响应、凭据或令牌。

### 4.2 详情与原有操作

选择实例后展示名称、客户/商品 ID、本地与上游绑定 ID、主机名/主 IP、状态、周期、续费金额、到期、最近同步和暂停原因等已存事实。这些字段直接从当前实例安全投影，不额外加载客户/商品关系、凭据或完整配置。缺失或已停用的旧连接如实显示，不能在读取时自动启用；换绑候选继续仅使用原有允许的活动经典连接。

保留“机器命令核对与历史”原路径；配置映射复核链接继续受 `upstream.mapping-review` 保护。不把未支持的映射/升级能力写成可用，也不在本批创建新的操作捷径。

| 原有操作 | 原权限与提交合同 |
| --- | --- |
| 暂停、恢复、申请终止 | `upstream.view` + `upstream.lifecycle`；`/admin/upstream-instances/{instance}/control`；保留 `action`、稳定 `request_id`、可选 `reason`、`confirm` 和 CSRF |
| 显式换绑 | `upstream.view` + `upstream.hotswap`；`/admin/upstream-instances/{instance}/hot-swap`；保留 `account_id`、`host_id`、`disposition`、真实 `reason`、`confirm` 和 CSRF |
| 原失败任务重试 | `upstream.view` + `upstream.lifecycle`；`/admin/upstream-tasks/{task}/retry`；保留失败任务条件、真实原因、对账确认和 CSRF |

“申请终止/操作入队”不写成已经删除/已经完成。换绑明确说明只绑定已有主机、不迁移磁盘数据，保留旧资源记录孤儿、终止处置需已认证 Deleted 的原语义。旧未决意图不因 UI 重试变成重新发单；原资金、幂等、审计、终态及绑定核验仍由 Controller/Action 执行。本批不改操作规则或增加批量危险操作。

错误不能被隐藏在已经关闭的对话框或折叠块里。失败时展开对应操作并展示具体错误，保留合法的原 `request_id`；只回填当前表单的非秘密标量字段，避免将一次操作的原因或选项复制到另一服务/另一操作。确认类勾选不自动恢复，需用户重新核对。

## 5. 权限、响应式与验收

未登录继续跳转 `/admin/login`；无 `finance.view` 或 `upstream.view` 保持对应 403/面板准入行为。仅查看角色能读取原有范围的本地事实，不出现退款、配置、生命周期、换绑或重试表单；直接 POST 仍由现有 Gate 拦截，不能只靠隐藏按钮。

桌面以 1440×1000 验收筛选、状态、金额和行操作的可读性；手机以 390×844 验收换行、独立表格横向滚动、详情卡单列与可达操作，文档整体无水平溢出。沿用浅/暗色变量、可见焦点及禁用动画偏好。对话框限制在视口内滚动，支持 Escape、关闭、焦点返回，不嵌套二次对话框。

| 验收面 | 必须覆盖 |
| --- | --- |
| 本地读取 | 初始 GET、筛选、分页、账单详情、实例详情均无外部 HTTP；无真实支付/通知/供应商动作 |
| 查询 | 有效组合筛选、清空、跨页条件保留、稳定排序、空数据/无匹配结果、非法参数及非经典详情拒绝 |
| 权限与旧入口 | 登录/仅查看/对应操作角色边界；原 POST、字段、CSRF、记录级 Gate 及确认条件不变 |
| 业务与保密 | 原定点金额、充值特例、各类状态语义；不输出密钥、支付原文、实例凭据或任务载荷 |
| 交互 | 桌面、390px、暗色；详情返回；分页；操作失败时错误可见及非秘密输入恢复 |

回归使用隔离测试库与模拟对端，预览只做本地只读/无效输入验证；不以 UI 验收为由操作真实订单、退款、主机或通知。

# 架构清理第五批：运行闭环验收方案

基线 `5049312`。用户指示“可以开始第5批”，对应终审计划的生产闭环验收，沿用验证后自动提交、必要时备份迁移的授权。本批先完成可重复执行的独立运行闭环，不将协议替身验收登记为真实生产收款或供应商交付。

## B5-01：同环境连接实际运行组件

- 使用专用空 MySQL 8、独立 Redis、APP_KEY、安装状态、storage、发布资源和配置缓存。容器 network=none、不发布宿主端口，PHP 通过独立 Unix socket 连接；不读取原预览业务数据、不接管共享服务。
- 实际 loopback HTTPS、专用证书信任、Nginx 与 PHP 8.4 FPM，Web/CLI/worker 以 www 运行。通过真实安装向导创建封印与管理员，并运行生产模式部署检查。
- Redis 承载队列、缓存、会话与共享锁，启用 AOF/noeviction；只测试本环境的中断与恢复。代码及业务 Action 保持原实现，不替换维护合同或使用 Queue/Http fake。

## B5-02：HTTP 与常驻业务链路

实际客户登录、CSRF、配置页生成默认值、本地报价、建单、支付发起、有效签名回调，经 Redis 常驻 worker 完成经典协议替身新购、续费和升级。精确核对金额、原请求重放、重复回调、上游唯一订单/付款、任务终态、交付密文与私密响应。SMTP 发送到本机接收端，核对持久投递结果与接收数。

由真实 scheduler 派发既有 maintenance Job，经实际维护 worker 和领域 Action 进入生命周期/目录队列；检查心跳、积压、原有独立队列及停止/恢复。独立巡检/watchdog 使用本环境状态，核对故障检测和恢复，不配置或发送外部告警。

## B5-03：证据与交付边界

脚本保留仅本批的私有证据、日志与进程/容器清理结果；仓库只提交脚本、必要修复和文档，不提交凭据、备份或生成缓存。原预览前后只读核对实际目标、持久表哈希、待处理任务及健康入口。

第5批隔离验收可证明真实组件在同宿主的运行链路；真实商户收款、公网支付回调、真实 ZJMF 扣款/开通、外部 SMTP 送达、生产域名和证书、实际 systemd/timer、值班人及外部监控、异机恢复仍须针对最终环境单独验收。实际支付和供应商动作需要明确商品、动作与额度，现有自动提交/迁移授权不包含未请求的真实外付、供应商变更或通知发送，依据 [工程执行授权](agent-guardrails.md)及 [部署流程](deployment.md#5-升级与回退)。

本批不新增 schema，不重写冻结规则，不继续迁移其余审计依赖或重做安装封印生命周期。原预览业务消费者/scheduler 保持原状态。

## 当前实现

`SyncClassicCatalogAction` 在原子导入/同步保护内保存配置组和子项两套 `linkage_pid / linkage_top_pid / linkage_level`。纯 `ClassicOptionLinkage` 校验两树：ID、直接父组、循环、孤儿、跨根/跨级、非默认路径与根标识必须一致。上游数据库默认 `linkage_level='0'`，连同空值/缺省均表示未展开冗余路径；解析依赖明确的 pid，不因默认路径拒售。非零的矛盾路径继续拒绝。

支持多个独立根、三级及更深链、同一根按不同父选项进入不同子组、合法叶节点。一个父子项同时对应多个子组的歧义结构明确拒绝：参考上游默认展开只取第一个匹配，不能自行把全部组累加，也不能声称已兼容该结构。非法树不发布半成品，重同步失败保留原商品、完整配置、人工隐藏状态和审计记录。

`ResolveProductOptionsAction` 从同步树和所选上游 ID 推导活动链；每个活动节点必须有属于当前父选项的合法选择和当前周期价格。缺根/缺子层、跨根、未知、隐藏和旧分支提交全部拒绝。非活动组不进入 pairs、报价、账单快照或上游参数；`QuoteLocalProductAction` 独立核对活动组及 pair 对应关系，防止错配价格。type20 每层按普通单选收费，保留15–19阶梯算法和原数量规则。

前端按父关系展开并重置失效子项、清空失效报价确认，禁用并隐藏非活动控件；FormData 只含有效链。多个根互不覆盖，控件 DOM 顺序可以与父子顺序不同。有结构后继但子项全隐藏或没有当前周期价格时保留必经层并提示不可选，不能成为免费叶。type20 页面在脚本初始化前禁用报价/购买并提示启用 JavaScript；普通商品保留原无脚本流程。250ms 合并、单个报价在途、过期响应丢弃、409二次确认和提交后原禁用状态恢复保持。

高级规则仅在涉及当前活动组时校验；已知非活动 type20 条件的 `sneq` 不触发，非活动 type20 结果不要求伪造选择。其他原 seq/sneq/数量规则不泛改。参考 `common.php::advancedConfigOptionFilter` 按实际提交配置遍历，但未找到其在参考项目购买后端的实际调用；本地明确实施的校验不能说成上游已完整强制校验。

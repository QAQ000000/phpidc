# 后台外壳与经营总览页面合同

日期：2026-11-20。基线：`ee24c2d`。本批为后台下一轮改版的 A 批：统一 Filament 外壳和已有公共组件，并增加默认经营总览。B1 运营与内容页、B2 库存 / 清算 / 运维旧页另批实施，不在本批声称全部翻新。

## 1. 外壳与导航

使用当前 Filament v5 面板，不引入前端框架、编译步骤或数据库迁移。主色统一为 `#2f54ea`，正文使用 full 内容宽度，桌面支持收起全局侧栏；手机继续使用面板原有导航抽屉。公共组件与系统配置样式共用基础 Token：字号 13px、圆角 8px、卡片内边距 18px / 20px、表格单元格 10px / 14px，暗色有独立颜色值。

现有六个可折叠分类及三十个业务叶子入口的权限、URL 和唯一当前项归属保持。经营总览是 `/admin` 默认页面，通过左上品牌首页链接返回，不另加第三十一个业务菜单项；不增加页内分类侧栏、重复横向主菜单或手机分类下拉。用户本轮明确要求首页改为经营总览，因此将 `AdminNavigationTest` 中旧的配置查看角色首页预期严格改为 `/admin`。原生可收起桌面侧栏会预渲染展开列表和收起下拉两套链接，因此 DOM 检查改为每种模式分别精确三十条、URL 唯一且不含记录路由；模型的六组 / 三十入口、分域权限、旧路径和当前项原严格断言保持。

图标使用本地已安装的 Heroicons，通过 Filament 正式 API 配置。组与子项图标遵守面板原生约束；图标辅助文字，不替代可读标签。详情页继续高亮拥有它的业务入口，不把账单详情、映射复核等记录路由列为新导航。

## 2. 首页与权限

`/admin` 为经营总览；品牌首页与登录后的面板首页指向该页面。继续使用原后台身份准入：匿名跳转 `/admin/login`，普通客户没有后台查看权限，停用或已注销账户不能因首页改版重新获得访问。

总览按已有查看权限分别执行查询与渲染。没有权限的区块不执行相应业务表查询，不先取全量数据再在 Blade 隐藏。不创建新的超级管理员旁路，也不把写权限并入查看权限。

| 区块 | 查看权限 | 展示与入口 |
| --- | --- | --- |
| 财务 | `finance.view` | 今日 / 本月 CNY 商品结算额（退款前）、待付款数量、待审批外部提现 / 转钱包及待核对支付事实；最近最多八条账单，进入原账单详情 |
| 服务 | `upstream.view` | 经典魔方已激活服务与未来七天即将到期服务数量；进入原服务列表 |
| 履约 | `tasks.view` | 失败履约任务数量；进入已有失败任务筛选 |
| 客服 | `support.view` | `open` 工单待回复数量与最近待处理工单；进入原工单处理入口 |
| 快捷入口 | 各目标页面及动作原权限 | 失败任务、待回复工单，以及有权限者的商品导入或系统配置入口 |

只拥有其他后台查看权限的操作者可以打开总览，页面说明当前没有可查看的统计区块，并展示其确实可访问的业务入口。不可将无权限显示为真实的零。

## 3. 指标与数据边界

“今日 / 本月商品结算额（退款前）”以账单为一单一笔：CNY、类型为新购 / 续费 / 升级、状态为 `Paid` 或 `Refunded`，并有处于本月起点至当前时刻的 `paid_at`。使用账单 `total_amount`，包含钱包与网关组合支付，排除充值和降级；退款后仍保留原商品结算额。它不是实收现金、退款后净额、收入或利润，不将冻结 / 解冻、充值、支付和佣金流水再混加入统计。

精确累计在数据库按单额分组并统计本月 / 当天笔数，再用模型 `decimal:2` 字符串、整数笔数与 `Money::mul/add` 合并。不对金额列执行数据库 `SUM`，不取全量历史账单到 PHP，不把 SQLite 聚合浮点结果当作精确账款。

日期区间采用应用配置时区的当天 / 当月边界，已结算时间上界为当前时刻，排除未来日期。服务区块仅统计经典魔方驱动：已激活数为 `Active`；未来七天到期数纳入 `Active` / `Suspended`，不将 `Pending` 计为运行、不将已过期服务混入未来到期。失败履约只计 `failed`，工单待回复只计 `open`，最近工单最多五条。待审批外部提现和转钱包按各自 `destination` 的 `pending` 计数；待核对支付只计 `payment_attention` 且状态为 `open` / `awaiting_clearance`。

统计保留财务历史主体，即使原客户已软删除也不借用户关联过滤掉原账单。最近账单最多八条，按 ID 倒序；只选择界面所需的编号、归属、类型、状态、金额、币种和时间等白名单字段。工单只投影待办所需信息，原输入按 Blade 转义。

总览普通 GET 为本地只读聚合，不能调用上游、支付、邮件、短信、实名、同步、重试、收款核对或应收完整证明流程；不解密订单、收款资料、凭据或卡密，不自动刷新供应商状态。计数和最近记录不预载秘密 JSON 或完整客户资料。

## 4. 页面与响应式

采用已有 `x-admin.card`、`table`、`badge` 等组件及统一颜色。页头显示经营总览和统计说明；按可见权限排布指标卡，底部为最近账单 / 客服待办及快捷入口。无对应区块时自然收拢，不出现无权访问或没有目标的按钮。

桌面 1440×1000 检查 full 内容、侧栏展开 / 收起与表格信息密度；手机 390×844 指标卡和双栏转为单列，长编号在本地容器换行或滚动，文档不横向溢出。浅色 / 深色的边框、文本、金额、状态和输入均可辨；状态同时使用文字，不只使用颜色。键盘可到达导航、折叠按钮与所有快捷入口。

## 5. 验收

独立新增 Feature 用例验证匿名 / 普通客户 / 分域操作者、空态、无权业务表不查询、金额精确与时间边界、状态与七天范围、最近八条稳定排序、软删除主体历史保留、安全链接与秘密不回显。禁止真实外部请求，通过 `Http::preventStrayRequests()` 与 `assertNothingSent()` 验证。

浏览器使用隔离 SQLite 和独立 storage，覆盖桌面 / 手机 × 浅色 / 深色、桌面侧栏折叠与手机导航、各权限组合和无数据状态。共享预览仅做只读健康检查；不为 UI 验收执行真实支付、开通、出款或通知。

最终运行全量 Pest、PHPStan、Pint 与差异检查，既有财务、授权和幂等断言保持。实际门禁、精确统计口径、浏览器证据和未完成范围另登记实施记录；通过后自动提交本批，现有无关文档和本地缓存不进入提交。

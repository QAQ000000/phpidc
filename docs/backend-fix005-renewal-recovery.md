# FIX-005：过期续费显式恢复闭环验收

日期：2026-11-18（Asia/Shanghai）。依据：用户明确批准 [C23](backend-remediation-decisions.md#c23--fix-005过期续费的显式恢复单)，对应 [问题清单 FIX-005](backend-review-remediation-2026-11-18.md#fix-005续费单过期后缺少恢复路径)。本轮只实施 FIX-005；此前未提交改动和用户的上游 API 总册保持。

## 行为与规则

- 根单保留唯一的 `{instance}:renew:{due_boundary_utc}` 与 Expired 终态。新增迁移文件只增加 nullable `renewal_root_id`、nullable unique `replaces_invoice_id`，均为 restrictOnDelete 自引用。恢复单保留 NULL billing_period_key/purchase_request_id，采用唯一前驱链；不搬移原唯一键、不改旧流水或旧券次数。INV-K1、章程和 guardrails 已按获准 C23 定向同步。
- 本人账单/服务页先 POST 报价，再通过稳定 ULID、加密短期 token、支付选择、确认框和原因 POST 确认。页面展示旧金额、新金额/优惠/钱包/网关分配、报价有效期及确认创建后的付款分钟数。报价期限默认5分钟、付款期限默认30分钟，均经 SettingService。报价可同步认证服务快照，但不创建账单、冻结钱包、消耗券或派发续费任务。
- 确认重新认证同步和读取续费报价，比较用户/服务/供应商绑定、到期边界、配置、价格锁定、上游成本、客户周期/初装费、币种、优惠、钱包/网关拆分及付款期限。变化即拒绝原确认，不擅自替客户接受另一金额。所有金额运算仍由 Money 完成。
- CreateComboInvoiceAction 保持唯一资金创建者：事务外询价，事务内先锁用户，再锁根/链及待付账单、实例、任务；MySQL 的未决任务采用锁定当前读。校验当前末端、逐单 freeze/unfreeze 流水、没有结算记录或该链履约任务；其他未决服务任务也阻止恢复。纯钱包/零额仍在同事务完成 Paid、唯一任务和账务记录，afterCommit 派发；原因审计和用券也在该事务内。
- 非 Expired、已结算、Cancelled/Refunded、仅时间超时但未实际解冻、缺失钱包释放证据、已终止/换绑/改币种/改到期边界、异常链或未决远端意图均不得恢复。若原操作预测的一个续费周期终点已经不在未来，转人工核实长期逾期起算及价格，拒绝自动恢复；不推测从今天重新起算。
- 调用身份加密保存于 `line_items.recovery.encrypted_request`，现有递归换钥覆盖它。相同键同参数即使报价过期或已换钥，也直接找到原单；同键改参数拒绝。另一键对已存在后继的前驱只定位后继，不二次扣款。后继再次实际过期，须针对新末端重新报价确认。
- 普通续费/调度按账期根单返回当前末端，已有请求 ID 重放仍返回该请求原单。支付发起、P8 回调和任务创建校验链末端。旧单迟到付款保持 P2：验签、去重、credit_in、告警、提交后 ACK，不支付恢复单，不重复续费、不再次解冻。
- 财务核查页只读展示根/前驱/后继和当前资格，沿用 finance.view；链接到各单已有的回调、支付尝试、财务流水及任务核对入口。没有运营代扣客户钱包接口。客户越权、原因/确认缺失、CSRF 被拒绝；报价 private/no-store，不把内部成本/指纹暴露给客户 JSON，token 不进入 URL、审计或错误闪存。

## 判断、失败说明与未验范围

1. 初稿PHPStan发现Invoice关联缺少泛型、fresh可能为空及重复空条件。补充真实关系类型、对已存在实例使用refresh、移除重复条件；没有类型伪装、ignore或baseline。锁定任务查询用first避免不必要全量集合，仍保留MySQL当前读。
2. 新测试初稿把“实例币种被改成USD”预期为DomainException；实际在询价前先命中实例与CNY根单不一致的ValidationException。修正新增用例的异常分类，保留严格拒绝、账单/钱包/流水不变断言，未修改任何旧用例。
3. 长期逾期、供应商外部手工续费/退款、实际起算点和并发远端配置变更仍未经真实写入验收。源码参考只证明版本中的行为，不证明目标供应商策略；一个周期终点已在过去的情况明确转人工。付款后远端发生变化仍由既有履约预同步/成本对账拦截，保留已付单和未决意图，不自动重买或退款。
4. 新字段只在临时库迁移。当前预览/业务库没有应用C22/C23迁移，新版结账/恢复功能上线须协调代码与数据库发布，不能把单元或离线验收当作已部署。
5. 原预览未停止/重启，`http://127.0.0.1:59493/up`仍200；只读检查账单/流水/任务1/2/1，客户钱包0.99 CNY、冻结0，恢复关系列不存在。没有真实续费、支付或机器控制调用，没有操作VNC。
6. 保留历史限制：旧verify-local-card-sale.py的“jobs总数=1”断言落后于运营通知/佣金派发，未获准改动，本轮未运行或声称通过；ClassicExpansion目录用例存在MySQL JSON键序敏感问题，此次MySQL子集不含该目录用例。详见FIX-004验收记录。本轮默认Gate全绿。
7. FIX-006～023仍按清单顺序处理，未将既有代码或Specs为0等同于这些任务完成。未提交Git。

## 资金与驱动检查单

- INV-I2/M3：Money金额恒等式、优惠不重复扣减；恢复确认只比较可信新报价。
- INV-W2/W3：用户先锁、唯一freeze/settle/unfreeze引用，重试与并发账务校验通过。
- INV-P1/P3：按gateway_amount支付；旧款仍P2、坏链P8拒绝留证；ACK在提交后。
- INV-L1/L3/L4：全局锁序、HTTP在事务外、驱动纯返回；替身在独立MySQL进程断言transactionLevel=0。
- INV-K1/K2/K4：账期唯一根/前驱唯一链、每单唯一任务、不返还旧券；当前末端才能结算。
- INV-P2/R1：复用原实例、没有新购实例或终止/退款行为；因失败不自动重开账单。
- INV-U1/Q1/K3：复用已核实的同步/报价/履约驱动日志和超时；不增加供应商协议或调度器。

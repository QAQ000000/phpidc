# U2 后台操作工作台实施记录

2026-11-20。依据 [已批准 U2 设计](admin-workspace-u2-design-2026-11-20.md)，按 U2a → U2b → U2c 顺序提交。沿用 Filament、Blade SSR、原生 dialog，无新增数据库迁移或前端构建链。

## U2a：客户工作台与全局左侧导航

- 总览独立置顶；六个可折叠分类按客户、商品服务、财务、运营、系统配置、通知运维组织。原 31 个入口完整保留，加总览共 32 个；逐叶子检查原权限，不添加分类级父 Gate。
- 客户详情使用八个普通 URL 页签，先校验页签与所属域权限，再查询当前客户和当前明细。概览不查询七类历史；历史页签不附带钱包与有效服务聚合。每类明细独立每页十条。
- 对象条合并姓名、编号与状态；概览只留账户资料和获授权指标。资料、钱包与更多操作仍调用原 C2/C3 Action，当前页签、分页与单层来源由固定白名单恢复。
- 公共导航支持旧记录锚点／分页到页签的固定映射，纯空 query 保留原 POST 默认返回。其余对象在后续两批逐一接入。

U2a 暂存树导出至独立副本后，八个相关 Feature 文件 **240 passed / 2407 assertions**。副本使用新 APP_KEY 与内存测试数据库，未读取部署配置。

## U2b：实例工作台

- 概览桌面双栏：状态、IP、到期与续费事实在左，获授权机器／同步／生命周期／换绑动作在右；手机先核心信息和动作。配置与计费、账单、任务、工单分别按页签读取。
- 生命周期与换绑表单进入工作台原生弹窗，原确认、Action、真实管理员、未决核对与 VNC 协议保持。普通 GET 不读远端菜单；只有显式 POST 才读取上游支持命令。
- 经典列表只保留一个实例工作台主入口。旧选中实例 GET 先按原客户过滤和权限验证，再安全转入主工作台；额外重定向保留 errors／允许回填输入，原无 tab POST 的返回契约不变。

代表截图：[实例桌面浅色](screenshots/admin-workspace-u2-2026-11-20/instance-1440-light.png)、[桌面深色](screenshots/admin-workspace-u2-2026-11-20/instance-1440-dark.png)、[手机深色](screenshots/admin-workspace-u2-2026-11-20/instance-390-dark.png)。

U2b 独立暂存树八个相关 Feature 文件 **214 passed / 1410 assertions**，包含旧经典操作、机器 HTTP 协议及 VNC；随后仅微调共用手机页头按钮换行，保留整按钮换行，避免中文按钮内逐字折行。

## U2c：账单工作台

- 概览左侧展示原支付计划、归属与时间，右侧展示实际收款事实及现有收退款动作。账单明细、支付尝试／回调、资金流水、履约任务与续费恢复按固定 URL 页签加载；履约任务继续独立 `tasks.view`。
- 实际收款仅投影原账单及原客户的 `settle:{id}`、`payment:{id}`、充值流水，不把计划网关额或迟到／超付回调当作原账单实际收款。无原始记账证据明确显示“未记录”，不由 Paid 标志推算。
- 线下凭证 GET 仅展示末四位；完整内容继续受审计 POST 读取，关闭清空。退款改为原生弹窗，原全额退款条件、原冻结和凭证唯一性不变。失败保持当前页签及允许回填输入，凭证编号和加密说明不回填。

代表截图：[未付账单桌面](screenshots/admin-workspace-u2-2026-11-20/invoice-unpaid-1440-light.png)、[已付账单手机](screenshots/admin-workspace-u2-2026-11-20/invoice-paid-390-dark.png)、[线下收款手机](screenshots/admin-workspace-u2-2026-11-20/invoice-offline-390-dark.png)。

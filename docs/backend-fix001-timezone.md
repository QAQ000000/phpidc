## 修复前行为

Unix `1794974400` 的真实瞬时值为 `2026-11-18T04:00:00Z`，即北京时间 12:00。旧驱动转为无偏移字符串 `2026-11-18 04:00:00` 后，消费者按上海时间解析，变成了提前八小时的瞬时值。

即便只修驱动为带偏移字符串，Eloquent 对 DATETIME 格式化时也会丢弃时区标记，因此必须在写库前转换到项目存储时区，不能只改驱动输出。

## 实际改动与决策

1. ZjmfFinanceDriver 输出带偏移 ISO 8601；缺失、空白和零值保持 null。Unix 时间戳的协议依据为参考源码 HostController 的 host_data 原样返回，以及本轮真实认证 header；不是按本机时区解释 Unix 秒数。
2. 新增 InstanceDueDate 统一解析及转换，写入现有 DATETIME 前转换到 `config('app.timezone')`，本项目为 Asia/Shanghai。ApplyInstanceSnapshotAction、ExecuteServiceTaskAction 的比较/提交和 HotSwapInstanceDriverAction 均使用它，overdue_since 的 UTC 事件边界也在入库前转换。
3. 带偏移字符串按其明确瞬时值转换。无时区字符串保留既有按项目时区解析的兼容行为；此项仅有隔离测试，不将其写成已验证所有供应商的线协议。
4. 保留原 INV-K1 的 UTC 续费键和冻结操作边界，不重写历史键、不修改已付款单，不执行真实暂停、恢复、重装、续费或采购。
5. 无 schema、冻结接口、DTO 字段、枚举或业务不变量变更（agent-guardrails §1.3）；驱动仍返回快照，写库仍在 Action，HTTP 在事务外（F10、INV-L3/L4）。金额及资金写入算法未修改。

# 经典魔方兼容修复第一批

日期：2026-11-19。基线：`0672e1c`。依据 `classic-product-configuration-audit-2026-11-19.md` 及源码复核后的三批建议。本批只处理发布保护、数量规则、下单资料展示、同步库存展示和确定不支持能力的新购准入；type20 完整支持留第二批。

## 实施范围

1. 共享导入 Action 覆盖后台、CLI 和直接调用。远端读取在事务外完成；基础资料、价格、完整配置及审计原子提交。新导入失败不留下公开半成品，重导失败保留旧资料和人工隐藏状态。后台不再另发一次完整配置读取。
2. classic `qty_stage` 存在时使用参考源码的绝对倍数或最小/最大端点规则；0/1 不增加步进限制。字段缺失时保留原 `qty_step` 起点偏移语义。前后端一致，不改变 15–19 的阶梯价格计算。高级条件和结果按配置类型识别数量，正确处理 `[0,0]`。
3. 从本人实例关联的原始购买加密快照投影下单资料，按来源、字段映射、隐藏和 `show_on_detail` 白名单过滤；密码默认遮盖，页面转义。不要写入实例的明文 `custom_field_values`，不要把完整购买参数交给模板；换绑、缺失或损坏的快照明确处理。
4. 复用已有 `stock_control/qty` 同步；前台展示最近同步的售罄状态，保留提交时实时核验，不恢复配置切换时的上游请求。预览仅部署目录专用调度和消费者，不启用其他未授权维护/通知/lifecycle 调度。
5. 配置快照只新增非敏感 `product_publisher_uid` 事实字段，对 `p_uid>0` 的开发者应用在新购收款前明确阻断。不能用商品名称或服务器分组推断 `hostid/serverid/os[]` 需求。其他特殊模块协议留第三批，当前不宣称全部兼容。

## 已批准决议 S1：新购售卖边界

推荐暂时阻止所有新的 `ontrial` 本地报价和建单；其余已支持的月付/一次性等周期不受此条影响。原因是现有接口只能读取配额，不能证明已用/预留额度和完整资格；现有 CDN 试用也有有限共享额度，缺少身份条件不等于无试用限制。额度和身份属于供应商连接账号，不能由本地客户资料替代。

推荐对缺少可信 `product_publisher_uid` 的旧快照，要求先完成一次完整配置同步再允许新购，不能把缺字段默认为零。当前预览在新规则部署前，通过目录专用同步更新已售商品的事实字段。

两条均只作用于新购：已有 `request_id` 的原账单幂等返回优先，已出账金额、已付款任务、支付回调、开通重试和生命周期继续使用现行流程，不因本批新售卖规则改写。新规则不得挂入同时供旧单履约使用的驱动 `validate()`。

S1 状态：用户已于本轮明确选择“采用 S1 推荐边界”。依据 `docs/agent-guardrails.md` §1.3：“Changing them requires a human decision”。该决定授权上述新购边界；不代表授权新增真实试用、购买、上游扣款或测试通知。

## 验收

- 导入后台/CLI/直接调用失败均不公开半成品，重导失败不破坏旧快照/人工隐藏；上游读取不持有业务事务。
- 数量规则覆盖最小1步进5、非倍数最大端点、0/1步进、原 `qty_step` 和高级零区间条件/结果；已有阶梯价格测试保持。
- 下单资料本人可见、他人拒绝；隐藏/未知/密码字段不泄漏，HTML 转义，坏快照不导致整页失败，实例明文 JSON 无新增值。
- 售罄/恢复/不限库存展示与最近同步事实一致，直接提交仍实时检查，目录消费者失败可观测。
- 新购准入拒绝时无账单、优惠券、资金或任务写入，旧请求与旧履约不被新售卖规则误伤。
- 隔离数据库执行 Pest、PHPStan、Pint；必要预览变更先保留可恢复备份，验证后分小提交。不得新增真实购买、上游扣款或测试通知。

本批没有计划新增数据库列或迁移。实际实现和验证完成后另记结果，不以计划文档代替验收。

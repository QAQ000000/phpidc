# U1：对象工作台页头与来源返回合同

依据：用户在旧后台 UI / 页面层级分析后回复“可以”。沿用六组可折叠全局左侧菜单、现有 Filament / Blade 与 `x-admin.*`，零迁移、零新增构建链。

## 页面与交互

- 客户、实例、账单详情采用共用工作台页头：对象名称与编号、中文状态、简要业务身份、返回直接来源按钮及原有相关操作。状态不得仅依赖颜色。手机端自然换行，长名称不撑出页面。
- 保留现有内容卡、客户页内锚点、权限及弹窗；不增设顶部模块导航、页内侧栏或分类 Tab。
- 列表进入详情后返回原筛选及页码。关联对象跳转只记住直接来源和对应区块，例如客户服务区 → 实例 → 账单，账单返回实例；不构建递归历史栈。
- 独立明细分页与普通 POST 成功、验证失败均保持经过白名单处理的当前页面上下文。机器菜单往返保持来源；VNC 继续走原签名协议，不追加未签名参数。
- 实例工作台进入旧经典状态操作／换绑详情后，带有效来源的两张表单也保持当前实例、筛选与固定操作锚点；无来源的旧 POST 继续使用原默认目标。
- 无来源的旧链接维持既有默认返回行为；账单现有平铺列表筛选参数仍兼容。保留旧路径与经典实例简要详情。

## 来源协议

- 使用独立的 `from` 查询数组，仅允许 `kind / id / query / section`，类型固定为 `customers / customer / instances / instance / invoices / invoice`。
- `query` 只含对应列表筛选及页码、或对应工作台独立明细页码；不含另一层 `from`。`section` 只允许当前对象已存在的区块锚点。
- 服务端从固定类型重建本地路径，绝不接收 `return_url` 或任意 URL。非法类型、非标量参数、无模块权限来源被丢弃，使用原默认返回；来源不授权目标读取或写入。
- 来源仅说明导航位置，不证明对象间业务关系、不进入资金/机器动作意图或幂等快照；不为来源查询客户姓名、解密凭据或请求上游。
- 目标页面照常鉴权并查询自身对象。已注销客户可在原有只读范围返回；目标不存在由既有 404 处理。权限失效时不展示其来源入口。

## 不变量与验收

- 不改业务 Action、金额、冻结、凭证、账户准入、生命周期、机器未决核对或审计归属。
- 保留现有敏感字段回填清理；上下文使用独立白名单，不扩大 `request()->all()` 的业务消费或回填。
- 基线与完成后运行 Pest / PHPStan / Pint；新增列表还原、跨工作台返回、分页、POST 成败、恶意来源和角色裁剪回归。隔离合成数据库浏览器检查桌面/手机、浅/深色及实际往返交互。
- 原 C4 客户服务区与经典简要详情的精确链接断言改为带该来源的完整 URL，仍严格要求每个经典／本地实例各一个入口；不改权限、身份、资金、隐私或幂等断言。无来源旧表单仍保留原默认回弹目标。
- 本批不执行真实财务、供应商或通知动作。通过后自动提交；远端推送等待用户明确请求。

## 后续商品工作区

本批只梳理字段和生效边界。下一批优先复用已有展示编辑与降价边界 Action、只读价格矩阵/上游配置、显式同步。加价、锁价、准入和主机名/密码规则编辑需先明确历史生效合同；不将有字段无消费者的开关展示为可用能力。

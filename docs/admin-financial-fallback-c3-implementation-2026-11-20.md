# C3 财务人工兜底实施记录

日期：2026-11-20，基线 `f36aa7b`。对应 [C3 实施合同](admin-financial-fallback-c3-contract-2026-11-20.md)。本批实现钱包可用余额加扣款、普通线下收款登记与既有账单工作台扩展；增加一条迁移、两张业务表，不增加前端构建链。最终门禁、隔离运行与截图结果在下文登记。

## 1. 钱包独立纠错

`AdjustCustomerWalletAction` 仅改变 `users.credit`，新增 `wallet_adjust_credit`／`wallet_adjust_debit` 方向类型；金额为严格两位 CNY 定点字符串，必须大于零。扣款不透支，加款按 `WalletCapacity` 校验可用、账单冻结、结清冻结三列及总容量。其余冻结、佣金、应收、账单和历史流水保持。

稳定 ULID 对应唯一 `adjust:{request_id}`；流水 meta 保存版本、原客户、实际管理员、方向、金额、币种和规范化备注。同意图返回原记录，不同意图或不同主体拒绝。调整与审计原子提交，不伪造充值、退款或应收清偿，也不创建通知事件。误操作使用新的反向调整请求纠正，原记录保留。

`AdminFinancialAccess` 在财务事务内按 ID 升序锁定实际管理员与原客户，并重新校验管理员当前访问许可及专权。新操作仅面向普通客户：本人、后台角色／直接权限账户及已注销主体均拒绝；已停用普通客户仍允许财务纠错，不恢复其访问。成功请求可保留历史幂等返回，但操作者当前权限仍必须有效。

## 2. 已收到的普通线下款

`RecordOfflineInvoiceReceiptAction` 首期支持银行转账和现金。必须填写可追溯凭证编号、实际收款时间并明确确认；备注可选 255 字，凭证说明可选、加密保存。仅接受未过期、未支付的 CNY 新购／续费／升级账单，金额严格等于原 `gateway_amount > 0`。已有任意支付尝试或回调、充值、纯钱包、降级、终态、自动续费待确认分配及缺少原资金／履约快照的账单均拒绝。

锁内保留原账单金额、优惠、付款分配与网关字段，核对原冻结流水的类型、归属、金额及未消费状态；只消耗原 `credit_applied` 冻结一次。原子写入 Paid、`settle:{invoice_id}`、`payment:{invoice_id}`、线下收款记录、原履约任务、通知 outbox 与管理员审计。复用 `CreatePurchaseFulfillmentAction`／`CreateServiceFulfillmentAction`，提交后派发，不在财务锁内请求供应商或发送消息。

服务账单核对归属、产品、币种、可计费状态、续费家族与未决任务；到期／绑定快照继续由原付款后的 worker 按既有契约核验，不新增“收款即保证上游操作成功”的承诺。原子事务对数据库可重试冲突最多重试三次；失败无部分入账，提交后派发只发生一次。

线下来源不伪造 PaymentCallback，不覆盖商户快照或交易镜像。真实回调晚到已 Paid 账单，仍按原重复付款规则入原钱包一次；Refunded 后回调保持原异常案件分支。全额退款继续使用原 `total_amount`，另核对线下分配、原收款及共享登记来源，并在新退款流水记录来源 ID；不重复解冻、不把迟到款混入原退款金额。

## 3. 共享凭证登记与迁移

迁移 `2026_11_20_000020_add_manual_financial_receipts.php` 新增：

- `offline_invoice_receipts`：原账单／客户／操作者、请求意图、分配快照、实际收款事实、加密说明及 payment／settlement／task 关联；请求与账单各自唯一。
- `external_collection_receipts`：普通线下收款与既有外部应收清偿共用的收款凭证占用，两个来源外键择一，唯一有效凭证键，保留已释放历史。

迁移在 MySQL DDL 前核验旧应收凭证，随后登记全部旧有效及已冲正来源。重复执行按原事实比对，不改旧账单、流水或应收。所有来源留存外键为 `RESTRICT`。原应收完整冲正才释放该场景有效占用，保留历史，并沿原纠正流程再次登记；普通线下账单不能借已冲正的应收编号另行结清账单。出款凭证登记仍使用原独立机制。

迁移其他已有真实应收来源的环境时，应暂停相关收款／冲正入口与仍加载旧写入类的进程，在备份后完成回填和一致性核对，再刷新代码进程并开放新入口，避免回填后仍由旧代码遗漏共享登记。当前预览应收来源为零，相关写入均走 HTTP 而非 worker；迁移前后来源与资金哈希核对通过，现有两个消费者也已刷新。

跨账户有效凭证由数据库唯一索引仲裁。线下入口查询应收历史使用带复合索引的锁定当前读，避免 MySQL REPEATABLE READ 事务早建快照后遗漏其他客户新登记又冲正的来源。新两模型保留事实，禁止普通删除／任意更新；仅原应收冲正允许释放。加密说明已纳入 `ReencryptSecretsAction`，轮换后资金事实及原请求重放保持。

## 4. 工作台、权限和隐私

保留 `/admin/finance/invoice?invoice_id=...` 及原退款路由／表单，新增原支付计划、实际来源、独立分页流水与按权限可见的任务。原六类、31 个左侧入口不变。客户详情加入钱包调整 dialog，账单加入收款及凭证详情 dialog，使用固定 `_admin_form` 和目标 ID 隔离失败回填。凭证编号与说明不存入错误回填，确认框不自动勾选。

| 入口 | 权限要求 |
| --- | --- |
| `POST /admin/customers/{customer}/wallet-adjust` | `customers.view`＋`finance.view`＋`finance.wallet-adjust` |
| `POST /admin/finance/invoices/{invoice}/offline-receipt` | `finance.view`＋`finance.offline-receipt` |
| `POST /admin/finance/offline-receipts/{receipt}/details` | `finance.view`＋`finance.offline-receipt`，记录查看审计 |

新增固定角色 `finance-wallet-adjuster`、`finance-offline-receipt` 分别只含财务查看与对应专权，不附赠客户、任务或退款权限。全部业务预设包含新角色，日常运营与财务只读不扩权；预设修改不批量赋权。

GET 使用本地安全字段投影，不解密收款说明、不查询上游、不做完整应收核验、不记查看审计。凭证编号只显示末四位；长度不超过四位时全部遮盖。只有明确点击详情才发受审计 POST，响应 `Cache-Control: no-store, private`，通过文本节点显示，关闭清除页面内容。请求意图与密文不进入模型默认序列化；审计不包含凭证说明或完整编号。

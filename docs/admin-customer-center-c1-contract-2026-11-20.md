# C1 客户查询中心与后台全局搜索合同

日期：2026-11-20。基线：`fb70879`。用户批准 C1 → C2 → C3 → C4，并明确要求 C1 同步角色预设、服务端分域搜索、带客户参数的业务直达及实用列表字段。本批只读业务数据，复用 Filament、`x-admin.*`、现有数据库和原生 JavaScript；不新增迁移或构建链。

## 页面与导航

- `/admin/customers`：客户列表；`/admin/customers/{id}`：客户聚合详情。保留原全局六类可折叠导航，在「运营与内容」增加「客户管理」，入口总数由 30 变为 31。内容区域不增加第二套侧栏或主分类 Tab。
- 顶部加入后台搜索，`GET /admin/search` 返回白名单结果；手机支持可达输入及有限高结果区域。搜索入口不替代左侧菜单。
- 保留原账单、服务、流水、工单、角色、审计和通知路径。已有详情保持原授权和操作，不借本批加入编辑、调账、封禁、代客登录、人工实名或发送通知。

## 权限与角色

- 新增固定 `customer-viewer` 角色，仅含 `customers.view`；同步 `AdminRoles` 标签、Web 可分配清单、日常运营／财务只读／全部业务权限预设，以及面板准入。新角色不附赠财务、上游、审计或角色管理权限。
- 客户列表／详情要求 `customers.view`。余额字段仅在 `finance.view` 后查询和呈现；服务数、服务摘要要求 `upstream.view`；工单、通知、审计、角色入口分别要求原 `support.view`、`notification.view`、`audit.view`、`access.view`。没有对应权限的区块不查询、不渲染。
- 客户基本资料、账户与邮箱验证状态、实名标志及已有脱敏实名历史属于客户查看范围；不读取密码、remember token、OAuth 主体／令牌、通知目标、凭据或证件原文。
- 不引入万能超级管理员 Gate。完整业务管理员通过既有固定角色组合获得新角色；既有日常运营／财务查看用户不会因预设修改自动被批量授予权限。核对当前预览已知管理员的角色，必要时用原受审计 CLI 定向补新角色；不创建新密码、不扩大普通客户权限。

## 客户列表

- 列：ID、姓名与邮箱、可用余额／账单冻结／结清冻结、有效服务数、实名状态、账户状态、注册时间。无财务／上游权限时不加载相应字段或聚合。
- 有效服务定义为本地 `Active` 或 `Suspended`，覆盖已落库各驱动记录；标明为本地有效服务，不把 Pending／Cancelled／Deleted／ProvisionFailed 计入。此处只读元数据，不增加各驱动的操作权限。
- 筛选：精确 ID、精确邮箱、姓名关键词、实名已认证／未认证、正常／已注销。默认只列正常账户；已注销通过显式筛选只读访问，保留匿名化后的字段，不恢复旧身份、不提供新写操作。
- GET 输入验证类型、范围和长度，非法参数返回明确 HTTP 错误；姓名通配符按字面值处理。列表分页 20，不逐客户加载业务集合或计算应收。

## 客户详情

- 首屏展示轻量资料和按权限裁剪的本地摘要。服务、账单、流水、工单、实名历史、通知元数据、账户自身审计分别分页或有明确最近条数上限；不为每个区块预载完整历史。
- 钱包保持三列原义，不把佣金余额或应收混入钱包总额。没有核验应收时不展示“无债”，不调用完整应收核验或准入服务。
- 服务只读 ID、名称、驱动、状态、到期与必要本地元数据；经典服务可跳现有实例详情，其他驱动只显示安全元数据，操作仍留待 C4。
- 区块右上角提供明确带 `user_id` 的原业务直达：账单、流水、经典服务列表、工单、通知日志、角色。目标页必须实际消费客户筛选；不生成看似过滤而实际无效的链接。
- 审计只展示 `subject_type=User` 且匹配客户 ID 的账户审计，沿用白名单投影；明确不是完整跨资源审计。审计直达同时携带 subject_type 和 subject_id，不把其他模型相同数字 ID 的日志混入。
- 账户已注销仍可查询已保留账单／服务事实；角色入口对已注销账户不开放。所有输出转义，敏感详情仍留在原受审计 POST。

## 全局搜索

- 每一域在服务端先授权再发查询：`customers.view` 搜客户 ID／完整邮箱；`finance.view` 搜账单 ID／完整账单号；`upstream.view` 搜实例 ID／完整上游 ID。数字同号返回明确分组结果，不猜测归属。
- 服务搜索对经典 ZJMF 使用现有后台详情；其他驱动仅在同时具备 customers.view 时返回安全元数据并跳所属客户服务分区，避免链接到不存在或无权访问的详情。
- 没有客户权限时，财务／服务结果不关联查询客户邮箱姓名。非客户域结果不携带原始支付、配置、认证、卡密、通知或凭据字段。
- 上游 ID 可能在不同连接重复，结果同时标记连接和本地实例 ID。所有链接服务端固定生成；不得接受任意回跳 URL。
- 搜索词至多 255 字符，每域至多 5 条，无全表模糊扫描、外部请求或凭据解密。客户端防抖、取消或丢弃旧请求；空词不查询，按钮与键盘均可操作。无模块权限不运行搜索。

## 性能与验收

普通页面及搜索只读本地库，不加资金锁、不产生业务任务、通知或审计写入，不请求上游，不触发全量应收扫描。角色部署沿原审计流程单独执行，不混入 GET。

新增有意义的 Feature 验证：匿名／普通客户／单域角色边界、分域不查询、预设与面板准入、分页和筛选、注销匿名化、余额与冻结的原义、服务状态计数、多连接同号、敏感列不投影、原链接参数实际生效。保留旧 Specs、旧严格业务断言和资金／身份／驱动规则；若旧测试仅固定 30 个导航入口，可按用户明确批准的第 31 个入口定向更新数量及导航断言，不能削弱权限或业务断言。

浏览器在独立 SQLite／storage／模拟账户中验收桌面／手机、浅色／深色、搜索键盘与移动结果、分页及业务跳转；留存模拟数据截图。共享预览只读健康核验，允许经原受审计 CLI 为明确的预览管理员补客户只读角色。全量 Pest、PHPStan、Pint、差异及截图完整性通过后自动提交；推送等待用户另行指令。

# 客户控制台页面合同

日期：2026-11-20。基线：`3075e20`。本批统一客户控制台的导航、公共组件与信息层级；不修改数据库、金融/归属/身份规则或外部接口。商城选购另列下一批，实施结果另写验收记录。

## 1. 导航与公共结构

登录后的客户页面只使用一套左侧主导航，统一入口为总览、服务、账单、钱包、账户安全、优惠券、推广佣金、工单和下载。详情仍归属对应入口高亮；外部提现归属推广、钱包结清归属钱包、注销归属账户，不新增页内分类侧栏、重复横向主菜单或手机分类下拉。品牌、用户信息和退出可在页头；商城/帮助等外部去向仍可访问，不把商城购买流程塞进控制台。

桌面主内容为页头、事实摘要、列表/详情卡和操作；手机收起同一左导航为抽屉。未登录的登录/注册/找回密码/第三方授权及公开下载继续可用，不能让匿名页面依赖登录用户或出现不可用的客户菜单。受保护地址继续跳转 `/login`；验证邮件等既有原地址返回规则保持。

复用 `x-console.page-header`、`card`、`badge` 和统一样式。卡片正文用 `.console-card-body`；可比较的事实使用 `console-kv`/统计卡，列表用语义表格和独立横向滚动区，金额与币种同列并右对齐。仅确有并列内容时用双列或三列；手机单列。危险入口与普通操作有文字区别，不增加无业务依据的原因、二次确认或通用表单引擎。

## 2. 页面与任务

| 页面 | 核心内容与操作 | 保留边界 |
| --- | --- | --- |
| `/console` | 本人服务/账单计数、待支付和近期记录、清晰入口 | 总览不展示服务密码/卡密，不冒充实时上游监控 |
| `/console/instances` 与 `/{instance}` | 本人服务筛选、状态/到期/周期/续费价、当前记录详情和原操作 | 单件秘密仍依原归属/状态/交付条件展示；读取/刷新/控制/续费各自原入口不混淆 |
| `/console/invoices` 与 `/{invoice}` | 本人账单筛选、历史金额分配、安全条目、原支付或续费确认 | 原付款状态、报价确认、网关/钱包条件与幂等字段保持；Paid 不代表已开通 |
| `/console/wallet`、钱包结清相关页 | 余额/冻结余额、充值范围与原申请/历史记录 | 定点 CNY、原上下限、启停、退款限制、出款证据与不确定状态不变 |
| `/console/account`、`/close` | 邮箱/密码、第三方绑定、Telegram 通知、手机号、实名、注销 | 就绪/验证/绑定/状态分支及密码/确认条件保持，不创建隐式绑定或注销动作 |
| `/console/coupons` | 领取券码、本人已领券、使用记录 | 领取不占用次数，使用仍复核；取消/退款不恢复次数 |
| `/console/affiliate` 与 `/external` | 推广链接、账面/申请占用/可申请金额、转钱包/外部提现、佣金/应收历史 | 只新注册归因、冻结快照、原请求 ID、应收阻断及不实际自动转账语义保持 |
| `/console/tickets` 与 `/{ticket}` | 关联本人服务搜索、新建、本人列表、对话、回复/关闭/重开 | 服务最多 50 个的实际范围、归属、开放/关闭状态与原 POST operation 保持 |
| `/downloads` 与 `/{resource}` | 资源名称/版本/访问级别/大小/摘要、授权下载 | 列表可匿名；实际下载继续由原授权判定，不直接公开存储路径或外部目标 |

只整理当前已实现入口；未实现的日期、渠道、批量动作或远程实时状态不画成可用控件。已有错误、状态及关键提示保留，长说明按对应业务卡就近展示。

## 3. 账户与运营细节

账户页采用邮箱密码、第三方登录、通知订阅、手机、实名和注销卡片。第三方绑定保留“先验证本地邮箱 + 当前密码”，相同第三方邮箱不自动合并。Telegram 登录绑定与通知订阅分开说明；原 `enabled` 开关只改变对应订阅。

手机号继续遮盖；邮件/SMS/KYC 未就绪时展示原不可用说明，不给无效的提交按钮。实名申请只显示脱敏摘要，保留真实姓名/证件号/当前密码/同意提交字段和待核验时的继续认证、查询结果入口；浏览器返回不直接改变认证状态。密码、验证码、证件号不回填，不把 OAuth subject/token、KYC provider 数据或手机号明文复制到 HTML/Livewire 状态。

优惠券页把领取表单、已领券列表和使用历史分开；金额保持原两位定点字符串。推广页把推广链接、资金事实、申请和历史记录分开，应收异常/完整核验链接继续清晰可见，不能把账面余额当可申请额，也不能因视觉调整省略应收阻断。

工单列表与新建表单分块；关联服务搜索使用原 GET `service_q`，不改变本人范围及 50 条上限。详情按时间显示客户/客服回复，用户文本转义并保留换行；关闭后只显示原“明确重开工单”，不能偷偷把回复当重开。下载列表仍只输出已有安全字段和本地 `/downloads/{resource}` 链接。

## 4. 请求、表单与保密

本批列表、筛选、分页和详情 GET 只读本地事实，不自动请求上游、支付、发短信/邮件、执行 KYC 或重试任务。显式读取按钮及变更操作仍走原 POST、节流、CSRF、Action 与权限/归属校验；不修改后端来迁就样式。

所有原字段名、隐藏请求 ID、`operation`、支付分配/报价 token、当前密码、同意/确认字段以及必填/可选条件保持。常规操作不新增必填原因。非秘密输入失败后可以按对应表单回填，使用标量类型检查避免非法数组导致渲染 500；密码、代码与证件不回填，确认不自动代用户勾选。页面错误和成功状态使用可见的 `role=alert/status`，不藏在关闭的折叠块中。

安全展示使用原服务/账单/下载投影；不得在摘要/列表额外渲染完整模型、秘密 JSON、上游成本、回调原文、支付凭据或远端 HTML。本人服务详情原本允许的交付凭据仍按原条件展示，不用统一脱敏把已交付内容变成不可取用。

金额沿用原定点字符串和 `Money`，不通过 JS/浮点重算余额或历史单据。无服务/空记录/未设置事实明确展示，不把未知价格、未同步状态或核验中余额写成零/成功。

分页采用轻量 `sales.pagination` 或等价语义结构，保留原查询和独立分页参数，禁止渲染撑满页面的默认巨大 SVG。推广佣金、转钱包申请、应收历史仍各自使用原分页名称。

## 5. 响应式与验收

桌面 1440×1000 验收单左导航、页头、信息卡、表格及金额可读性；手机 390×844 验收抽屉、单列卡片、自然换行与可触摸表单，长表格只在自身容器滚动，文档无水平溢出。焦点可见；表单标签关联输入；状态同时用文字与颜色表达；正文/长链接/工单对话不撑破卡片。

| 验收面 | 必须覆盖 |
| --- | --- |
| 登录与归属 | 匿名保护路由跳转、公开下载/认证页兼容、外人服务/账单/工单拒绝、本人列表不混入外人事实 |
| 业务分支 | 账单支付/钱包与应收阻断、服务秘密条件、邮箱/手机/KYC 就绪状态、工单关闭/重开及下载授权 |
| 表单 | 原 URL/字段/CSRF、密码不回显、非秘密错误回填与错误可见、非法数组安全回退、原请求 ID 保留 |
| 本地读取 | 页面 GET 不产生外部 HTTP/通知/资金变化；试验使用隔离库、模拟对端 |
| 视觉 | 桌面/390px、详情归属高亮、卡片层级、表格滚动、轻量分页，无内层侧栏或重复主导航 |

本批不更改后端/数据库、不改旧测试断言，不操作真实支付/退款/通知或供应商资源。未完成的商城选购改版不计入本批完成度。

# 后台公共组件与商品列表页面合同

日期：2026-11-20。基线：`5c43836`。用户确认按“公共组件规范 → 后台商品列表样板 → 订单/实例 → 客户控制台 → 商城选购”推进。本文件约定本批样板和后续复用边界；验收结果由实施记录登记，不在设计阶段声称已通过。

## 1. 本批页面与信息层级

本批以 `/admin/upstreams` 的经典魔方商品列表为样板，保留“上游商品与连接”现有导航位置及所有连接、导入、同步、配置边界表单。它展示经典魔方商品，不将本地卡池、Sub2API 商品或其他驱动混称为已完成的全商品管理。

采用现有 Filament 面板壳。6 个全局左侧分类及其叶子入口保持，当前入口唯一高亮；手机通过同一左侧抽屉访问菜单。列表按“页头操作 → 筛选 → 结果表格和分页”排列；进入当前商品配置详情后，内容区改为该商品的事实与配置卡片，提供返回列表入口。不再增加分类 Tab、内层侧栏或手机端菜单下拉。

连接配置与导入属于页面操作，放在页头的明确按钮中。按钮打开有标题的对话框，原有表单完整保留；浏览商品时不先铺开全部连接编辑区。商品配置由行内“配置详情”进入，明确选择一件商品后才加载其选项组、子项和边界表单。若通过 `?product=ID` 标识当前商品，它是记录钻取参数，不是新的分类菜单。

## 2. 公共组件合同

本批只抽取已在样板使用的样式和语义结构。后续页面按相同结构复用，不建立任意列配置、任意动作执行或运行时拼接权限的通用表格引擎。

| 组件 | 外观与行为 | 约束 |
| --- | --- | --- |
| 页面操作区 | 标题说明与主要动作并排；小屏换行 | 主要动作有文字，图标不单独承担含义；隐藏无权限动作 |
| 筛选条 | 有标签的搜索框、真实支持的下拉、查询和重置 | 使用 GET；回车可查询；重置恢复本页默认筛选和第一页 |
| 列表卡片 | 结果数量、语义表格、空状态、分页 | 没有数据仍显示表头和空状态；不虚构加载进度 |
| 数据表格 | `table/thead/tbody/th scope`；固定表头；清晰行分隔 | 金额和操作右对齐；ID/版本次要显示；复杂内容不挤进每一行 |
| 状态徽章 | 文字结合颜色表示状态 | 不仅靠颜色；显示/隐藏、缺货、连接停用等事实分开表达 |
| 分页栏 | 显示实际总数与当前页范围，保留有效筛选 | 使用服务器分页；稳定排序；筛选后从第一页开始 |
| 详情信息块 | 标题、键值事实、相关操作与可展开的复杂内容 | 只为当前记录加载复杂关联；无关列表记录不预载全部选项 |
| 操作对话框 | 标题、说明、关闭、提交/取消，限制在视口内滚动 | 支持 Escape、键盘焦点和返回触发点；不能嵌套另一个对话框 |
| 反馈 | 成功、字段错误与操作错误清晰可见 | 失败反馈说明对应操作；密钥不进入错误回显 |

危险操作确认对话框是后续需要时复用的交互模式，是否使用取决于现有业务风险。浏览、筛选、读取目录、普通保存和同步不新增“确认一次才能确认”的步骤，也不把可选审计备注改回必填。退款留服务、冲正和未知结果释放等原有明确授权及证据要求保持；本批不添加这些业务入口。

## 3. 商品列表样板

### 3.1 筛选和请求

支持条件以本地查询实现为准：关键词（商品名称或明确标识）、经典连接、商品本地显示状态。URL 保存这些条件，分页链接继续携带有效条件。没有真实实现的日期、标签、全局状态或分类条件不出现在界面上。输入做类型和长度校验，不把用户输入拼接为 SQL、任意排序列或任意关联名。

初始 GET、筛选、分页和打开商品详情均只读本地库，不读取远程目录、核价或同步。列表本身不使用连接是否可达作为渲染前提；读取上游目录与同步仍由操作者显式提交原 POST 动作。

### 3.2 行内信息

表格优先呈现商品名称/本地 ID、所属连接/上游 PID、本地展示状态、已同步库存事实、基础计费信息和操作。版本、配置组数量等可作次要文字。展示的数据来自现有已同步事实，不能把“有目录版本”称作实时同步成功，也不能把“已配置连接”称作连接正常。

`is_hidden=false` 单独只表示“显示”，不等于客户当前一定可购。分类隐藏、连接停用、S1 准入与同步库存等条件继续由原售卖逻辑执行。库存未知不显示为零；无限库存与有限库存明确区别。若列表显示价格，必须标明币种、周期和“基础价”，不把未选择配置的基础价格当作含全部配置、优惠与设置费的最终订单价。金额仍使用定点字符串与现有 `Money` 规则，不用浮点重算。

行操作保留“查看配置界面”、显式“同步配置与价格”和进入本地配置详情。配置详情显示原选项组、子项、隐藏状态及未来续费降价边界；选项未加载前不展示一个可编辑但不完整的替代品。商品/配置详情不存在或驱动不匹配时明确拒绝，不回退到另一件商品。

### 3.3 连接与导入操作

经典连接和 Sub2API 连接均继续使用原字段、POST URL、CSRF、Action 和权限。经典连接保留客户账户、JWT 兼容模式和信用额度回退选择；Sub2API 已有站点地址保持只读，更换站点仍须新建连接。密钥输入为空，编辑时留空保留原值。页面和 Livewire 状态不包含解密后的密钥。

导入保留原连接、上游 PID、周期、币种、加价和可选备注。仅打开对话框不会读取目录、导入商品或同步配置。对话框关闭不提交；提交错误时自动重开对应对话框，并在框内显示具体错误，继续保留该表单的非秘密字段。

## 4. 权限、状态与响应式

| 场景 | 页面合同 |
| --- | --- |
| 未登录 | 继续跳转 `/admin/login`；不先泄露商品或连接信息 |
| 无 `upstream.view` | 保持原 403/面板准入行为 |
| 仅查看 | 可以筛选、分页和查看允许读取的事实；不显示连接保存、导入、同步或边界保存表单 |
| 有配置权限 | 显示对应连接表单，保存仍由原 Controller/Action 再次校验 |
| 有导入权限 | 显示导入、商品同步及降价边界原入口；无权者不能靠直接 POST 绕过 |
| 没有商品 | 清楚提示尚未导入；有导入权限时给出同一导入操作入口 |
| 筛选无结果 | 显示“没有匹配商品”和重置；不误称目录为空 |
| 没有经典连接 | 导入区说明先配置连接，不能提交无连接的导入请求 |
| 连接停用或商品隐藏 | 展示真实状态；浏览本地记录不触发自动启用或自动发布 |
| 保存或同步失败 | 保留原错误与审计语义，不显示成功，不泄露秘密 |

桌面以 1440×1000 为验收视口：筛选和操作布局紧凑，主要事实可扫读；长表格滚动时表头保持可辨认，操作列不会与金额混排。浅色和深色均使用同一组组件颜色变量，并覆盖徽章、边框、输入、悬停、焦点和对话框。

手机以 390×844 为验收视口：页头和筛选自然换行，表格在自己的可聚焦滚动容器内横向滚动；文档整体不超出视口。重要字段和操作保留，不用无说明的隐藏列代替可操作性。对话框宽度不超过视口、内容区域可滚动，关闭和提交可通过触摸与键盘操作。禁用动画偏好继续生效。

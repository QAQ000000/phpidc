# 经典魔方兼容第二批：type20 层级联动

用户在第一批验收后指示“开始下一批”，继续已讨论的第二批范围：同步两套父子关系、配置页切换分支、本地报价与新购提交支持 type20。沿用“验证后自动提交、必要迁移备份后执行”的授权。本批复用现有 JSON，不新增数据库列、DTO 或枚举，不执行真实购买、扣款或通知。

## 实施边界

1. 同步在现有 group.upstream_meta / subs 中保存配置组与子项的 linkage_pid、linkage_top_pid、linkage_level。校验父级、跨组关系和循环；不完整结构沿用第一批原子发布保护。多个独立根可并存，一个父选项可按不同选择进入不同子组；无法确定唯一后继的歧义结构明确拒绝，不能自行累加。
2. 服务端从已同步结构及客户选择推导有效链；每个活动节点必须显式选择合法、未隐藏且支持当前周期的子项。旧分支、跨根子项、未知组和缺失节点拒绝。客户端隐藏不是服务端验证依据。
3. 按有效整条链逐级累计周期费和设置费，仅有效节点生成快照并传给上游。type20 为普通单选，不使用15–19阶梯价格。保留现有数量步进、阶梯价格、Money 计算和 checkout 实时核价/显式确认。
4. 前端父项变化后重置失效子项，仅启用并提交当前链；多个根互不覆盖。结构上有后继但当前周期无可用价格时提示不可选，不能省略收费层。高级联动与非活动节点的组合依据上游源码确定，再补对应测试。
5. 本批支持新购，不扩展尚无法正确表达分支删除的升降级、降级边界和换绑核验；这些入口对 type20 明确拒绝，避免误算或错误批准。

## 源码依据

参考项目 `/www/wwwroot/zjmf-manger-decoded` 只读：`ProductModel::handleOptions/handleSubs` 分别构造组树和子项树；`ConfigOptions::webChangeTwoArr` 根据所选父子项选择下一层；`Cart::optionHandleLinkAgeLevel` 输出完整有效链，核价与落库对有效各组分别处理。第二批不采用仅末级计价或父项偏移数量规则。

- 隔离同步、两级/三级与多根链、切换分支、无后继、无当前周期价、非法结构及伪造提交回归。
- 隔离 HTTP 本地报价 → 实时价格确认 → Paid → fake 上游提交，核对有效配置、资金恒等及无副作用拒绝。

# C3 财务人工兜底实施合同

日期：2026-11-20，基线 `f36aa7b`。用户已验收 C2 并明确指示推进钱包加扣款、普通线下收款登记与 FinanceInvoice 工作台。本合同落实本批四条财务边界，必要迁移、隔离实测及自动提交沿用既有执行授权；真实资金操作和真实通知发送不在本轮验收范围。

## 四条边界

1. **钱包调整只改可用余额。** 独立 `wallet_adjust_credit`／`wallet_adjust_debit` 流水，金额为 CNY 非负定点字符串且大于零，不使用正负号表达方向。仅改变 `credit`；不改账单冻结、结清冻结、佣金、应收、历史账单或旧流水。扣款不得超过可用余额，加款遵守 WalletCapacity 完整三列容量。它是补差／补偿／纠错账项，不冒充支付回调、充值单、应收清偿或退款。独立专权，稳定 ULID 请求与原子审计；误操作通过新的相反方向请求纠正，不删除原记录。备注可选255字，不新增必须编写的原因。
2. **普通线下收款只结清当前准确应付额。** 首期仅登记已实际收到的银行转账或现金（`bank_transfer`／`cash`），凭证编号、实际收款时间和确认必填；可选凭证说明加密保存。仅 CNY、未过期 Unpaid 的新购／续费／升级，`gateway_amount > 0`，登记金额必须精确等于原 `gateway_amount`。不接受易支付交易号冒充线下款，不接充值、降级、纯钱包、终态或自动续费待选择账单；不改原价格、优惠、分配、网关、商户快照或交易镜像。已有支付尝试或回调的账单转原收款核对流程，本普通入口拒绝，避免覆盖在途资金。
3. **收款与业务同事务闭环。** 用户升序→账单／续费家族→支付尝试→实例→任务→资金证据→收款凭证→通知。锁内校验原 `freeze:{id}` 的归属、类型、金额及未消费状态；只消耗原 `credit_applied` 冻结，不返还再扣钱包。Paid、`settle:{id}`、`payment:{id}`、持久线下凭证、履约任务、通知 outbox 与真实管理员审计原子提交，afterCommit 派发；失败全回滚，无锁内外部 I/O。线下凭证使用独立业务表，不伪造 PaymentCallback。原真实回调在账单 Paid 后到达，按原重复付款规则一次入原钱包，容量异常继续原案件；Refunded 等分支保持原契约。退款仍为原 total_amount 全额，明确追溯线下来源，不重复解冻／充值。
4. **工作台扩展只承载这些能力。** 沿用 `/admin/finance/invoice?invoice_id=...`，保留所有旧路由及退款权限，显示原金额分配与实际结算来源、分页关联资金流水／任务及独立线下收款记录；普通 GET 只读本地、不解密凭证、不请求供应商或完整应收核验。查看敏感凭证使用专权受审计 POST。保持单一全局左侧导航；使用 x-admin 组件／原生 dialog／固定表单标记与目标ID隔离回填。手工建单、改价、部分退款、合并账单、余额自动抵应收、C4服务干预不属本批。

## 权限、身份与幂等

新增固定 `finance-wallet-adjuster`（finance.view＋finance.wallet-adjust）和 `finance-offline-receipt`（finance.view＋finance.offline-receipt）角色；不附赠客户／服务／审计查看。原运营、财务只读预设不扩权，全部业务预设包含新角色。客户中心的钱包调整入口还需 customers.view；账单工作台只需原 finance.view。预览仅给完整管理员 #3 定向新增这两个角色，#2保持原角色。

所有写操作锁内重新校验实际操作人有效及专权。目标为普通客户，拒绝本人、任意后台角色／直接权限、已注销／匿名化主体；已停用普通客户允许管理员纠错／收取原有账单，不恢复其访问，不代发新订单。业务所有者始终是原 user_id，不能按可复用联系方式定位资金。

调账以唯一 `financial_transactions.reference_key=adjust:{ULID}` 持久去重，meta保存固定版本的请求意图（owner、actor、direction、amount、CNY、备注）；同键同意图返回原记录，无重复审计／资金变化，不同意图或不同主体拒绝。旧 `adjustment` 保留兼容只读，不重写历史。

线下记录 `offline_invoice_receipts`：request_id唯一、invoice_id唯一，原用户／操作者／金额／CNY／渠道／凭证编号／received_at、请求意图、原分配快照、payment/settlement/task关联、加密证据。强制同键同意图幂等，金额与事实表为业务证据，不依赖审计读取。

新增共享 `external_collection_receipts` 收款占用登记，银行／现金凭证与既有外部应收清偿互斥；两种真实来源外键择一，使用唯一 active_receipt_key。迁移先校验并登记已有应收凭证，不能默默略过冲突。应收既有完整冲正才释放该场景的占用，保留历史；新线下账单不得借应收已冲正旧凭证绕过原纠正流程。原应收纠正流程仍必须绑定原已冲正条目。调用者按稳定凭证键排序认领，数据库唯一约束是跨账户竞争兜底。新增凭证不向原支付回调补写虚假网关事件。

## 迁移、密钥与验收

仅追加迁移创建上述两表并登记旧应收来源，不修改旧迁移／历史资金。所有关联留存外键 RESTRICT；证据模型禁止普通更新删除，开放的释放仅限既有应收冲正。加密证据加入离线密钥轮换，隐藏于模型序列化及 GET。原金额、隐私、权限、身份、幂等和 Specs严格断言保持，新增enum／角色定向更新精确集合断言须记录。

Pest／PHPStan／Pint、锁序与跨场景凭证竞争、钱包容量与扣款不足、重复及冲突请求、原冻结证据、支付竞争、退款、通知失败回滚、密钥轮换及隔离桌面／手机明暗验收均须通过。预览先一致性备份、隔离副本迁移比对，再实际迁移并定向赋权；原客户、钱包、账单、服务不执行真实业务动作。自动提交，推送等待另行指令。
